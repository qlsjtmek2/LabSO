# LoL Adaptive Build & Strategy Optimizer (LabSO) - 요구사항 명세서

## 1. 프로젝트 개요

### 1.1 목적
리그 오브 레전드(LoL) 플레이어가 상대 챔피언과 조합에 맞춰 최적의 아이템 빌드를 구성하고, 장인(Expert)의 플레이 데이터를 분석하여 전략적 인사이트를 얻을 수 있는 웹 애플리케이션을 구축한다.

### 1.2 범위
- **플랫폼**: 웹 애플리케이션 (Web)
- **대상 사용자**: 전략적 우위를 점하고 싶은 모든 LoL 플레이어
- **핵심 가치**: 데이터 기반의 객관적 빌드 추천 및 상위 플레이어의 동선/판단 벤치마킹

---

## 2. 기능적 요구사항 (Functional Requirements)

### 2.1 콤보 데미지 계산기 (Static Calculator)
- **우선순위**: High
- **기능 설명**: 사용자가 챔피언, 아이템, 콤보 순서를 입력하면 예상 데미지를 계산한다.
- **세부 요구사항**:
    - 챔피언 선택 및 레벨 설정 (1~18)
    - 아이템 슬롯(6칸) 구성 및 룬 설정 (주요 룬)
    - 스킬 콤보 시퀀스 입력 (예: Q -> 평 -> E -> R)
    - **결과 출력**: 물리/마법/고정 데미지 총합 및 쿨타임 반영 결과

### 2.2 장인 분석기 (Expert Analysis)
- **우선순위**: High
- **기능 설명**: 특정 고수(장인)의 최근 매치 데이터를 분석하여 플레이 패턴을 시각화한다.
- **세부 요구사항**:
    - **소환사 검색**: Riot ID (Name + Tag)로 검색
    - **매치 타임라인 분석**:
        - **위치 히트맵**: 3분, 5분, 10분, 15분 대의 주요 위치 시각화 (정글 동선/로밍 파악)
        - **빌드 순서**: 상대 라이너(Matchup) 별 아이템 구매 순서 및 시간
        - **스킬 마스터**: 상대별 스킬 선마 순서
    - **제약 사항 (Web 한계)**: 리플레이 파일(.rofl)의 마우스 클릭 단위 정밀 분석은 웹에서 불가능하므로, **Match V5 Timeline API**를 활용한 "이벤트/위치 기반 분석"으로 대체한다. (클릭 타이밍 -> 스킬 사용/킬/오브젝트 이벤트 타이밍)

### 2.3 적응형 빌드 추천 (Adaptive Context Engine)
- **우선순위**: Medium
- **기능 설명**: 내 챔피언 vs 상대 챔피언 및 적 조합에 따른 아이템을 추천한다.
- **세부 요구사항**:
    - **상황 입력**: 내 챔피언, 상대 미드, 적 정글, 적 전체 조합 특성 (AP/AD 비중 등)
    - **추천 로직**: 통계 데이터 기반 승률 높은 아이템 및 "장인들이 이 상황에서 선택한 아이템" 제시

## 3. 비기능적 요구사항 (Non-Functional Requirements)

### 3.1 성능
- **API 응답**: Riot API 호출 캐싱을 통해 재검색 시 1초 이내 응답
- **계산 속도**: 콤보 데미지 계산은 클라이언트 사이드에서 즉시 처리 (< 100ms)

### 3.2 제약사항 & 규정 준수
- **Riot Games API Policy**:
    - API Key 관리: 백엔드에서 안전하게 관리 (클라이언트 노출 금지)
    - Rate Limit 준수: 개발 키(초당 20회) 및 프로덕션 키 제한에 맞춰 요청 큐(Queue) 구현
    - "No Cheat" 정책: 게임 중 실시간 정보를 제공하거나 플레이를 대신하는 기능 배제 (Pre-game/Post-game 분석에 집중)

---

## 4. 데이터 전략 (Hybrid Strategy)

### 4.1 정적 데이터 (Static Data)
- **DataDragon**: 챔피언 기본 스탯, 아이템 정보, 스킬 계수, 이미지 리소스
- **업데이트**: 패치 버전 변경 시 자동/수동 업데이트 스크립트 필요

### 4.2 동적 데이터 (User/Match Data)
- **Match V5**: 게임 종료 후 결과 데이터 (빌드, KDA, 룬)
- **Match V5 Timeline**: 분 단위 위치 좌표, 아이템 구매 타임스탬프, 스킬 레벨업 로그

### 4.3 리플레이 데이터 한계 극복
- 웹 환경에서는 `.rofl` 바이너리 패킷 파싱이 불가능함.
- **대안**: "리플레이 업로드" 기능을 "Match ID 입력/검색"으로 대체하여 Timeline 데이터를 심층 분석하는 형태로 구현. (사용자가 파일을 올리는 불편함 제거 및 기술적 실현 가능성 확보)

---

## 5. 기술 스택 (Tech Stack)

- **Frontend**: Next.js (React), Tailwind CSS, Recharts (차트/히트맵)
- **Backend**: Next.js API Routes (Serverless)
- **Database**: PostgreSQL (Supabase) - 매치 데이터 캐싱 및 사용자 즐겨찾기 저장
- **External API**: Riot Games API (Match-V5, Summoner-V4, Spectator-V5)
